# 单目标声线转换项目开发规划

> **当前执行方案（2026-10-15，用户已确认并要求开始）：** 陌生输入者先录准备音频，算法生成转换配置，加载后启动实时变声。准备音频不作为正式输出，换人重新准备；后续新句单独评价音色，不能只验证升调。配置生成入口与9项主机检查已通过，尚未真人准备录音或接入实时C++。下文“免录入”和自动首句缓存属于已被本方案覆盖的历史。见 [实现与下一步](../report/prepared_conversion_20261015.md)。

> **最新候选思路（2026-10-15）：** 用户提出陌生输入者本次先录入分析、算出转换参数，再开始输出。纳入自动起始分析候选；输入者无需已有源档案。初始等待、缓存首句如何输出和换人重估需单独验证，尚未选定时长或证明目标音色效果。此候选允许当次先分析，补充下方较早的免校准表述，不恢复此前20秒录音安排。见 [思路与验证边界](../report/automatic_start_analysis_20261015.md)。

> **当前权威要求（2026-10-15）：只注册目标，任何未录入、未校准的输入者直接讲话即可转换。** 不得要求源档案、选择输入者或预读校准句。此前按人校准路线不满足要求，仅留作对照；源校准录音安排取消。优先验证未见源说话人的音色转换与目标注册能力，再优化有效算法的板端性能。下方允许源校准的旧规划已被覆盖。详见 [需求修正](../report/source_uncalibrated_requirement_20261015.md)。

> 核心要求补充（2026-10-14）：多个不同输入者均须转换得接近同一已注册目标声线。用户今天反馈其他人试说时相似度不足、像统一升调；现有固定基频倍率/谱包络变形未实现按输入者校准的映射，多输入者目标相似度未通过。恢复后优先验证源校准、源到目标映射和跨输入者留出句，不能以自然连续或固定倍率代替目标相似度。大小声适应仍最后处理；本次仅保存需求，今天继续暂停，不启动板卡或构建。 [详细验收](../report/multi_input_requirement_20261014.md)。

2026-10-09执行更新：用户已指定截止日期2026-11-06并授权Codex全盘接手。实际日历与当前责任以根目录[总计划](../plan.md)为准；以下相对20天安排保留为原阶段设计与验收依据。音频外设接板上接口，优先核对WM8960与厂商Linux驱动。

## 1. 目标和优先级

周期按约10天学习准备＋20天开发组织。若学习已完成，直接执行开发D1；若总剩余时间只有20天，学习应融入各自任务，取消额外10天准备，减少增强功能。暂不绑定赛事截止日期，由B在D1核对实际提交节点。

| 层次 | 内容 | 验收含义 |
| --- | --- | --- |
| 基础交付 | 单目标现场录入、参数生成及保存、麦克风实时输入、目标驱动音调转换、原声对比、PL参与处理 | 即使音色研发未达标，仍有稳定板上作品；只能据实报告已完成能力 |
| 主要研发目标 | 在基础链路上增加经软件验证的音色调整，使输出比仅音调转换更接近目标 | 以留出句盲听和独立评价验证；未证明改善则不宣称已完成目标音色拟合 |
| 后期提升 | 2～3个目标档案与平滑切换 | 单目标正式验收后再安排，延期开发，不挤占报告和复现时间 |

本期不安排多人混音分离、同时多路输出、神经网络现场训练、完整RVC/LLVC上板、独立HDMI界面和PL网络协议栈。隐私评价可后续研究，不作为本期必须功能。

## 2. 推荐实施路线及待验证点

先完成软件参考与板上旁路，再接入一条时域变调数据通路。优先研究循环缓冲、插值、交叉淡化的实现；F0估计和目标统计先放在PS。C并行验证音色处理，只有软件结果优于普通变调，才迁移已选定的处理模块。不要同时重做PSOLA、完整FFT/IFFT及LPC极点变换三条路线。

仅注册目标，输入者无需预先录入或校准；必须评估未见说话人直接输入与换人场景。必要的输入特征在推理中提取，在线统计不能变成隐式预校准流程。清音、静音和低置信度F0不能强行做基频映射，应有明确的保持/旁路规则。

音色候选从受限谱包络修正或少量平滑滤波参数开始，C比较留出语句效果。平均频谱受句子、麦克风和录音距离影响，不能直接当作纯粹的人物音色；不能把固定均衡器或降低MFCC距离等同于声音身份转换。LPC/McAdams只作为候选实验，极点求解、滤波稳定性和实时重构均需评估，不能预设为容易移植。

| 位置 | 首期职责 | 后续可迁移 |
| --- | --- | --- |
| PS | 录入、质量检查、F0估计、源/目标统计、参数管理、音频调度、界面和日志 | 经测量确为热点且有明确收益的特征运算 |
| PL | 音频缓存、变调、插值、交叉淡化、限幅与控制接口 | 软件已验证有效的滤波或谱处理模块 |
| 开发电脑 | 算法实验、参考输出、盲听材料、可选独立声纹/ASR评价 | 不承担最终板上实时变声；若使用PC协同必须单独标注 |

音频接口D2前选择一条：已有可靠板载Codec时评估直连PL；否则先验证USB声卡经PS的双向音频。选定后统一时钟、采样率和测量方式。开发参考建议单声道16kHz、有符号16位PCM；若设备仅稳定支持48kHz，明确采集格式和重采样位置，不强行套用16kHz设备配置。

USB路线将设备/驱动缓冲、PS调度、DMA和算法全部计入延迟；直连PL路线仍需计入Codec与算法缓存。PYNQ用于配置与调试，实时循环避免逐样本Python调用及同步绘图；必要时使用独立音频工作线程或C程序。

## 5. 三方接口约定：D3冻结v1

由B维护一份接口说明，A和C共同审阅；具体寄存器地址由实际地址图产生，本计划不预编造。

- **音频格式**：设备和算法各自采样率、单声道选择、PCM位宽与符号、端序、32位流字中的打包/符号扩展方式、块长和有效样本数。
- **流接口**：DMA路线的每次传输字节数、块尾TLAST位置、TKEEP、背压行为、接收先就绪的启动顺序和超时恢复；传输块不等同于算法窗，不能每块清空变调状态。
- **目标配置**：版本、采样率、有效语音长度、F0统计、音色参数、参数合法范围；不合格录音不得覆盖当前有效配置。
- **控制**：旁路、启停、复位、目标参数提交及生效边界、输入者重新校准、状态查询。后续扩展只预留配置版本，不实现多目标管理。
- **数值规则**：每级定点格式、舍入、饱和、滤波器系数稳定范围、预填充时间、启动/结束尾部及复位后的状态。
- **监测**：样本/块计数、DMA超时、音频xrun、队列欠载/溢出、削波及处理耗时；区分不同错误来源。

## 6. 验证与验收

下列为工程目标，不是已测得性能。D3根据设备基线冻结延迟预算并留存记录，不得在正式测试后改指标掩盖失败。

| 项目 | 方法 | 通过或报告要求 |
| --- | --- | --- |
| 现场注册 | 新建、保存、重启加载、重录替换；静音/削波/过短输入 | 正常流程各3次可复现，异常录音给出原因且保留旧配置；录音长度初试30～60秒，按有效语音量调整 |
| 基础变调 | 正弦及真实语音、升/降/旁路、参数变化 | 稳定段正弦主频比例误差目标≤2%；边界回绕、复位、背压不破坏序列 |
| 定点正确性 | 同一PCM送定点参考、RTL及板上 | 约定相同运算规则的路径逐样本一致；与浮点参考的误差另报，不能混作一致性标准 |
| 延迟 | 同步录制参考输入和实际输出，重复至少30次 | 报p50/p95/最大值；暂以p95≤100ms为工程目标，D3验证可达性；变声后使用可辨识标记/包络等测法并说明误差，不能直接依赖波形相关 |
| 持续实时运行 | 连续30分钟，含讲话/静音/参数调整 | 目标无不可恢复中断、无DMA超时和音频xrun；报告实测计数、欠载及处理耗时高分位，不只写“听起来流畅” |
| 音色逼近 | 原声、仅变调、完整候选采用同一留出句 | 随机盲听比较目标相似度和自然度；完整候选须较仅变调有可重复改善，否则列为未完成研发目标 |
| 内容保持 | 相同留出句的人工转写或固定ASR | 报字错率和相对原声/仅变调的变化；暂定不恶化超过5个百分点，按样本数量解释结果 |
| PL价值 | 同一板卡、采样率、算法及块设置下比较PS-only和PS+PL | 报CPU占用、计算及端到端延迟、量化误差、LUT/FF/BRAM/DSP和时序；传输开销也计入，不承诺一定加速 |
| 可复现性 | 非原作者冷启动并按文档注册、转换、导出 | 记录完整工具/镜像/依赖版本及工程版本，演示可重复 |

数据最小规模：1名授权目标说话人＋至少2名其他输入者；每名输入者准备10句未用于调参的语句，并保留独立会话。目标注册音频与目标测试参考也分开，尽量匹配测试内容和录音条件以减少句子、设备差异。先做安静室内，噪声与跨音域作为压力测试。

盲听建议邀请至少5名不知处理顺序的听者，分别评价目标相似度、自然度和可懂度，保留每条评分及样本数量。小样本结果只作为初步证据。单目标无需A/B/C目标分类矩阵；比较转换前后与目标的相似度变化即可。

若使用MFCC/频谱特征驱动转换，相同特征距离只能作为诊断；不能用“优化过的分数变好”单独证明听起来像目标。可在电脑离线使用独立说话人模型补充评价，仍需盲听和内容保持结果。MFCC/VQ识别不负责生成声音。

## 7. 风险与降级决策

| 检查点 | 风险 | 处理及范围变化 |
| --- | --- | --- |
| D3 | 镜像或双向音频不通 | B主责定位设备/驱动，A/C协助；先暂停界面和增强。文件回放仅用于继续开发，不能替代实时功能验收；无法解决则重估日期 |
| D6～D9 | 音色候选未超越仅变调 | C保存失败样例，停止该候选硬件化；保留基础作品，音色仍标为研发未达标 |
| D9 | DMA/音频块调度不稳定 | A/B联合处理接口，C提供短固定向量；暂停新特征，不临时更换整套系统 |
| D12 | 运算超预算或资源不足 | 缩减候选复杂度，将低频配置/特征工作留在PS；保留一个实际参与变声的PL核，并重测总延迟 |
| D15 | 尚有断流、爆音、时序失败 | 回到最后稳定版本，取消音色增强并记录损失；剩余时间优先基本正确性和复现 |

音调转换保底不等于整体创新目标已完成；若音色提升未得到证实，应在报告中说明完成边界，不能通过更换指标包装成真人音色拟合成功。本计划不再给无实验支撑的完成概率或移植天数。
