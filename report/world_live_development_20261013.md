## 已实现

`src/ps/world_live_stream.cpp` 接收/输出raw管道，录放由 `board/live_world_trial.py` 监督的arecord/aplay承担。内部分析采用40ms滑窗，算法配方与昨天滑窗候选一致，使用已对齐的持续合成器。

| 阶段 | 处理及容量 |
| --- | --- |
| 采集线程，CPU0 | 实板32kHz S24_LE双声道只取左声道24位，127抽头因果FIR降到16kHz；每块128样本，输入FIFO最多64块/512ms |
| 分析线程，CPU0 | 只保留160ms历史和当前块所需40ms未来，窗口实测最多3712样本；参数FIFO最多8块 |
| 合成线程，CPU1 | 单一WORLD状态，16个所有者槽，库指针越过后才释放；保持连续相位并排空EOF |
| 输出线程，CPU1 | 输出FIFO最多32块/256ms；127抽头FIR上采样到32kHz，S24_LE左右复制；暂用180ms静音前缀建立缓冲 |

FIFO满时背压，不静默丢样本。参数和样本总数在退出时核对。采集/分析/合成/输出相互独立；I/O阻塞不会在合成线程内直接调用write。Linux非阻塞read/write配合poll，5秒无I/O进展返回7；SIGINT/SIGTERM唤醒退出检查，SIGPIPE转换成错误码。Windows测试适配使用二进制管道，不把主机阻塞I/O适配当作Linux超时验证。

因果采样率转换每次63/32000=1.96875ms群延迟，总约3.9375ms。前缀不推进WORLD编号或状态；结束只写实际音频长度，额外80个合成样本仍仅排空尾部。滤波末端没有另外输出127抽头全尾巴，长度固定，最后约2ms边界不能当作完整滤波尾响应验收。输出饱和计数非零返回6，不宣称无削波。

输入缓存约64KiB，输出缓存约32KiB，滑窗约30KiB，参数数据和库内部空间另计；队列容量是上限，不是固定新增延迟。180ms前缀还会叠加ALSA/硬件缓冲及因果滤波延迟，不能直接作为实测端到端延迟。
