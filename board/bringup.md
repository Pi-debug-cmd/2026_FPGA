# 板卡和音频启动检查

本清单用于D1～D3收集实际证据；以下命令在板端Linux执行，不在Windows直接执行。当前未建立板卡连接，未执行这些命令。

## 需要记录

| 条件 | 记录内容 |
| --- | --- |
| 硬件 | 核心板/底板版本、完整器件型号、原理图与厂商PS工程路径 |
| 工具 | Vivado版本、安装目录、可运行的仿真程序 |
| 系统 | 厂商镜像来源、内核、Python与PYNQ版本、启动步骤 |
| 音频 | USB声卡或Codec型号、麦克风/耳机、稳定输入输出格式 |
| 网络 | 板卡连接方式及网络地址；不在公共报告记录密码 |

板端只读检查：

```bash
uname -a
cat /etc/os-release
python3 --version
python3 -c "import pynq; print(pynq.__version__)"
cat /proc/asound/cards
arecord -l
aplay -l
```

没有PYNQ或ALSA工具时记录实际报错，先核对镜像能力。已有正常启动镜像优先保留备份，不根据芯片相同直接更换为其他厂商镜像。

## 双向音频验收

1. 选定实际录音/播放设备，先查看支持格式，再选稳定采样率、通道数、PCM格式；命令中的设备ID须来自本板枚举结果。
2. 录制短语音并从板上耳机播放，记录格式和错误日志。若设备仅支持双声道48kHz，先保留原生格式，另测单声道提取与重采样。
3. 空处理连续录放至少10分钟，记录xrun、缓冲尺寸与处理块长。使用耳机避免声学反馈影响检查。
4. 测设备到设备延迟，至少30次；保存测量信号、测法和误差，不把软件调用耗时当音频总延迟。
5. 单独完成PS→DMA→PL旁路→DMA→PS回传，验证有符号边界、块尾与多块连续传输。

G1只有实际双向音频和PL回传均成功才通过。文件回放可继续算法开发，但不能代替实时麦克风验收。
