# 三人团队分工建议

对应 [`topics/topic.md`](../topics/topic.md) 的六个候选。原“多设备声学巡检”因与已有声音识别演示的核心链路相似而移出候选；新声学题专门验证混合声音中的多标签并发检测，另有一题评估实时语音匿名化。以下按角色分配，成员姓名和最终题目待团队确定后填写。每人都须能讲清完整数据链路，不能把 PS、PL、报告完全割裂。

## 通用分工原则

| 角色 | 主要责任 | 每日可核查产物 | 集成时必须交付 |
| --- | --- | --- | --- |
| A：PL 与时序负责人 | RTL/HLS 核心、仿真、Block Design、引脚与时序、bitstream | RTL/HLS 提交、仿真结果或综合报告 | `bit`/`hwh`、地址图、资源/时序报告、接口说明 |
| B：PS 与系统集成负责人 | PYNQ 镜像、Overlay 调用、AXI-Lite/DMA 驱动、数据采集与演示 | 能运行的 Notebook/脚本与运行日志 | 一键演示入口、板端日志、接口对照与环境记录 |
| C：算法、验证与报告负责人 | 场景定义、黄金参考、测试数据、自动校验、性能测量、报告与演示 | 样本/期望输出、校验记录、指标表 | 可复现测试、PS/PL 对比、报告、视频脚本 |

三人共同负责：第 1 天核对野火板卡的硬件资料、实物接口、PYNQ 镜像和赛事组别；第 5 天确定接口契约；第 12 天共同完成首次板上闭环；最后 3 天相互复现和答辩演练。若野火板没有可用 PYNQ 镜像，B 先评估移植所需时间，并与 A/C 一起决定采用板卡现有 Linux 镜像下的 PS 程序；不可直接烧录 PYNQ-Z2 镜像。A 不应等到算法全部完成才开始仿真，B 不应等到 bitstream 完成才写数据输入，C 不应等到最后才开始采集基线。

## 题目 1：串口偶发故障前后轨迹黑匣子

| 人员 | 具体任务 | 完成判据 |
| --- | --- | --- |
| A | 实现 UART TX/RX、CRC-8、序号检查、BRAM 环形记录、触发前后冻结和 AXI 访问；做正常/误码/跳帧/超时及缓冲区回绕仿真；按野火原理图绑定引脚 | 四组故障与回绕仿真通过，上板 TX→RX 外部跳线闭环，冻结位置与预期一致 |
| B | 验证 PYNQ 或现有 Linux；实现 Overlay/PL 加载、控制寄存器与 BRAM 读取、轨迹还原、CSV 记录和时间轴图表 | 冷启动后按 README 可复现 10 分钟运行，故障前后字节及时间顺序正确显示 |
| C | 定义测试帧、触发窗口和故障注入清单、Python 黄金参考、PS 解析基线、捕获率/定位时间测量和报告 | 四类故障各 3 轮有原始轨迹；报告含捕获窗口、误差、存储量、资源与限制 |

**接口交接**：A 与 C 共同签定帧格式、CRC 多项式、记录结构和触发窗口规则；A 与 B 共同签定寄存器/BRAM 映射、冻结与重新武装方式；B 与 C 共同签定 CSV 字段与基线测量方法。第 5 天冻结第一版接口，改动需三人记录原因。

**可复用技能包**：三人共同把“AXI-Lite 寄存器契约、Overlay 自检、黄金参考对比、资源/时序数据采集”整理成可换题目的 `skill/`，由 C 维护 README，A/B 各验证一次。

## 题目 2：纸质资料拍摄质量评分与重拍提示器

| 人员 | 具体任务 | 完成判据 |
| --- | --- | --- |
| A | 灰度流块级亮度/梯度内核、边界处理、DMA/寄存器返回、仿真与资源时序 | 各块统计与黄金参考一致，首末行和非整块边界有测试 |
| B | 图片输入、灰度缩放、PYNQ 传输、结果热图与重拍提示界面 | 30 张图片可批量上板跑完，记录端到端处理时间 |
| C | 自采图片及标签、PS 基线、阈值选择、三类提示准确性/误报分析、报告 | 调参集与测试集按图片隔离，提供错误案例和可复现指标表 |

**接口交接**：第 5 天冻结图像尺寸、块大小、像素顺序和输出格式；第 10 天用 3 张固定测试图完成 PS/PL 比对，之后才增加摄像头。C 的标注标准应由 A/B 各复核一轮，减少主观偏差。

**可复用技能包**：块级流处理黄金参考比对工具和端到端性能计时模板，由 C 主写、A/B 上板验证。

## 题目 3：混合声音中已知事件的并发检测与取证

| 人员 | 具体任务 | 完成判据 |
| --- | --- | --- |
| A | 定点窗缓存、频带特征核、DMA/AXI-Stream、量化误差与时序资源 | 连续窗口不丢样，PL 特征与 PS 参考逐窗对齐 |
| B | 野火板音频接口核验、WAV 回放/现场采集、Overlay 调用、重叠时间轴与证据导出 | 可复现单源和双源现场混音；不能现场采集时准确标注回放范围 |
| C | 三类声音录制和留出会话、多标签 PS 基线、相对音量/重叠比例实验、误报漏检分析 | 第 3 天给出混音基线是否成立的证据，最终报告含并发漏检与单标签对照 |

**交接与技能包**：第 3 天三人共同决定是否保留该题；第 5 天冻结采样率、窗长、频带与定点格式；B/C 提供固定测试 WAV 和标签，A 保证仿真与上板同一输入结果一致。整理音频 DMA、TLAST、定点参考和留出录音评测方法。

## 题目 4：多传感器数据可信度与故障归因提示器

| 人员 | 具体任务 | 完成判据 |
| --- | --- | --- |
| A | 多通道滑动统计、缺样计数、BRAM 事件窗及 AXI 接口 | 正常共同变化、单通道故障、回绕和重武装仿真通过 |
| B | 至少两路实物采集、时间戳/有效位格式、板上控制和证据导出 | 第 4 天确认实物与参考实验可行，之后可复现两类现场事件 |
| C | 制定共同变化及断线/卡死/移位测试、PS 规则基线、归因评价 | 给出正确归因、误报、漏报和“证据不足”案例的原始记录 |

**交接与技能包**：A/B/C 共同确定传感器接口、单位、采样频率、丢样定义和外部参考；B 的原始记录由 C 标注，A 使用同一记录做仿真输入。整理多通道时间对齐、故障注入与证据追溯模板。

## 题目 5：隐私约束下的区域占用与异常滞留统计

| 人员 | 具体任务 | 完成判据 |

| B | 回放和 USB 摄像头接口、区域配置、匿名事件 CSV 与展示 | 自采视频可批量回放；界面只输出任务所需统计 |

**交接与技能包**：第 5 天冻结分辨率、块大小、区域坐标和事件定义；第 10 天先完成固定回放比对，再考虑摄像头实时输入。整理图像块级黄金参考、状态机标注与数据留存说明。

## 题目 6：固定目标声线的实时语音转换与隐私评估

| 人员 | 具体任务 | 完成判据 |
| --- | --- | --- |
| A | 先评估软件转换模型的计算热点与 Zynq-7020 资源，再决定可实现的 PL 核；随后完成 DMA、逐帧黄金参考和板上加速测量 | 只有在高质量软件基线成立后投入 PL；PS/PL 输出对齐，端到端收益有实测 |
| B | 野火板双向 USB 音频链路、固定目标参数加载、缓冲调度、听音演示与端到端延迟测量 | 第 3 天前完成空处理回环，最终连续运行并记录中位数及高分位延迟 |
| C | 获得目标人及输入者录音同意、整理至少三位输入者的留出句子、建立高质量软件基线并组织自然度/目标相似度盲听、报告 | 在 PL 开发前证实软件输出具有可接受的目标相似度和可懂度；最终给出失败案例与完整指标 |

**交接与技能包**：三人先依据 B 的音频回环和 C 的软件盲听结果决定是否继续；若真实性或实时音频任一门槛未过，暂缓本题，不以轻量变声替代原目标。通过后再冻结 PCM、帧长、重叠、缩放和唯一目标声线参数；A/B 使用 C 的固定测试音频逐帧和端到端校验。整理双向音频缓冲、DMA 定点比对、延迟测试及隐私评测边界。真实目标声线只使用本人授权样本，演示标注为转换语音。

## 工作量与风险控制

- 最初约 10 天每人都需学习 Vivado 2018.3 工程、AXI 和基础验证；若有适配野火板的镜像，再学习 PYNQ 2.4 对应 API。角色分工表示主责，不表示只学自己的一块。
- 开发期每两天做一次板上演示。任何功能连续两天没有可验证进展，三人共同缩减功能到 `topic.md` 的最小闭环。
- 报告与复现由 C 统筹，A 提供真实资源/时序报告，B 提供板端日志和环境信息，禁止用估算值替代实测。
- 与大模型的提示词、回答、人工纠错和验证结果从第一天开始存档；最终技能包须写适用范围、操作方法、失效条件和验证证据。
- 选题确定后，再把成员姓名、具体设备和赛程日期填入根目录 `plan.md`；此文档只提出分工方案，不预先替团队确定人选。
