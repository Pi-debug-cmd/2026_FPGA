# 01 素材与任务边界：把"我以为"变成"清单里写着"

日期：2026-10-09 ~ 2026-10-21
相关文件：`ai_collaboration/prompt_log.csv` 第 1–6 行；原始逐日摘要
[`appendix_ai_worklog.md`](appendix_ai_worklog.md) 第 40 行；`a3_neural_feasibility.md`（原仓库 `report/`）

## 1. 这一轮要解决什么

接手的是一堆历史资产（别人交接的语料、模型、报告、板端二进制）。最大的风险不是"算法不会"，
而是**对素材规模的错误认知**——它会让所有"泛化性"结论失效。

## 2. 提示词要点

> "根据现有文件开始全盘接手项目……先读 `AGENTS.md`、`project_guide.md`、最新
> `handoff_*.md`、`coummucation.md`、`plan.md` 和交接包；**先做资产核对，不要先改代码**。
> 对每一项素材给出：文件数、时长、SHA 是否一致、能证明什么、不能证明什么。"

要点：**要求先做"能证明/不能证明"的划分**，而不是先给方案。这条后来救了很多次。

## 3. 模型的关键决策 / 输出

| 决策 | 依据 |
|---|---|
| 不采纳"4 名留出说话人"的说法，逐文件核对 manifest | 4 段 screen 语音的说话人 ID 都是 `SSB0434` |
| 训练集规模按 manifest 重算 | 训练 **192 对 / 20 人**；验证 8 对 / 2 人 |
| 明确任务三级（保底/进阶/最终），且前一级未过不得认领后一级 | `plan.md` |
| 目标只绑定 `Track 5–8`，`Track 9` 留出，不参与任何拟合 | `project_guide.md` |

## 4. 被证伪的假设与纠正过程

### 4.1 "有 4 名留出说话人，所以已经能说明多人泛化"

- **当时判断**：交接文档写"4 段 screen 语音"，看起来是 4 个不同的人。
- **怎么证伪**：逐条读 manifest 的 `speaker` 字段 + 看录音元信息 → 4 段全是 `SSB0434`。
- **纠正**：验证集实际是 **8 对 / 2 人**；训练集 **192 对 / 20 人**。
- **影响**：任何"多人泛化已通过"的表述被撤回；后续多人验证必须重新采集，
  且不得用同一人的变调版本冒充多人（这条写进了 `plan.md` 的门禁）。

### 4.2 "素材很少，只有几条，先凑合训"

- **当时判断**：从"4 段/5 段"这类描述推断语料很小。
- **怎么证伪**：把 `交接/` 全量清点：8399 文件 / 4,180,670,234 字节，
  大小与 SHA256 全部一致；其中 `student_corpus_expanded/` 有 **192 个源句 + 192 个教师伪标签**，
  文本 192 条互不相同，且开发测试句"下午我沿着小路…"**不在训练文本中**（无文本泄漏）。
- **纠正**：不是"几条素材"，是 **192 对、约 14.8 min**、20 个说话人。
- **影响**：训练/评估的统计口径整体改写；"泛化不足"的解释从"数据太少"变成
  "源域不匹配（干净 44.1 kHz 数据集 vs 板端 16 kHz 采集）"。

### 4.3 关于"音高 +12 半音"的记错（团队记录，未在本机复核）

- **当时判断**：某轮对照里把 `Track 12` 的音高差记成"升 12 个半音"（一个八度）。
- **纠正**：团队复核后的记录是 **+6.2 半音**（约 1.43×），而不是 +12。
- **说明**：这条的原始报告没有留在本机（属于早期聊天记录），因此**在这里只作为方法论示例，
  不作为可复核证据**；本包内所有引用的音高比例都以可复核的 `1.4`/`1.394`/`86856` 为准。
- **教训**：**任何"差多少"的结论都要用算法从音频里量出来**（本项目用 WORLD f0 中位数），
  不能从别人的口述里继承。

## 5. 沉淀

1. **先清单、后方案**：素材的"能证明/不能证明"必须在写第一行代码前定稿。
2. **规模类事实必须能 grep**：说话人数、对数、时长、SHA —— 每一条都要有文件里的落点。
3. **口述数字一律降级为待验证**：+12 vs +6.2 就是例子，代价是一个八度的判断错误。
