## 3. 算法实现（与 Python 参考逐项对应）

链路（`src/vc_stream.cpp`，全部 double 内部精度，仅 MLP 用 float）：

1. **输入**：S24_LE 32 kHz 双声道裸流。板上 `S24_LE` 是**32-bit 容器 + 24 位有效位左对齐**（`arecord` 2 s 写出 512,000 B = 32000×2×4 B，与 `bringup_tool wav24` 的 `(int32)(v*8388607)<<8` 一致）。
   取左声道：`x = (int32 >> 8) / 8388608.0`，即"低 24 位有符号 ÷256 得 PCM16"的浮点等价形式。
2. **32k→16k**：127 抽头 Hamming-sinc，`fc = 7500 Hz`，抽头归一化到直流增益 1，抽样偏移取奇数样本使群延迟为**整数 31 个 16 kHz 样本**（见第 11 节坑 6）。
3. **SoundTouch 升调 1.40**：`setPitch(1.4)`，`SETTING_SEQUENCE_MS=30`、`SEEKWINDOW_MS=10`、`OVERLAP_MS=10`、AA 滤波开，16 kHz 单声道，`putSamples/flush/receiveSamples`。输出按 Python 习惯 pad/截断到原长度。
4. **WORLD 分析**（原始信号）：`InitializeDioOption` → f0_floor 75 / f0_ceil 400 / frame_period 10 ms / speed 4 / allowed_range 0.1 → `Dio` → `StoneMask` → `InitializeCheapTrickOption` + `fft_size=1024` → `CheapTrick` → `InitializeD4COption`（threshold 0.85）→ `D4C`；`logsp = ln(max(sp,1e-16))`，513 bin。
   - 在 float32 精度下与 `pyworld` **完全相同**（`max|Δ| = 0`，见第 8 节）。
5. **特征**（逐行照抄 `train_student.frame_features` / `train_v5.utterance_stats` / `stack_context`）：
   - 32 阶输入 DCT 倒谱 `ceps = logsp @ dct_in.T`，减去句内均值 → `ceps_c`；
   - 68 维 = `[ceps_c(32), logf0_rel, voiced, gain_rel, apmean, Δceps_c(32)]`；
   - 上下文 ±4 帧（`np.pad(mode="edge")`）拼成 612 维；
   - 句级统计 34 维 = 32 维平均倒谱 + `median(log f0)` + 浊音比例；
   - 合计 **646 维**，用 blob 里的 `mu/sd` 逐维标准化（float32 除法，与 numpy 同）。
6. **MLP**：4×512 GELU（**精确 erf 形式**，不是 tanh 近似）+ 48 维输出；`ceps48 = logsp@dct_out.T + res`，`logsp_pred = ceps48 @ synth`（`synth = pinv(dct_out).T`，导出时算好，板上不做 pinv）。
7. **包络移植**：`diff_db = 0.5*(pred - src_env)*(20/ln10)`，逐 bin 限幅 ±20 dB；静音帧判定 `rms < max(1e-4, p95(rms)*10^(-45/20))`，经 `[0.25,0.5,0.25]` 平滑成 0..1 的 mask，`gain = exp(diff_db*ln10/20*(1-mask))`，`Y = X*gain`，源相位不动。
   - 分母 `src_env` 取**升调后信号自身**的 WORLD 包络（与 Python B 路完全一致，不是原始信号的）。
8. **ISTFT**：librosa 语义（periodic Hann、`center=True` 零填充、按窗平方和归一化、`length=len(xB)`）→ **16k→32k**（同款 127 抽头插值）→ S24_LE 双声道（左右同信号）。

### 与任务描述的 3 处偏差（都是为了"与 Python 数值对齐"）

| 任务描述 | 实际实现 | 原因 |
|---|---|---|
| "STFT win1024/hop160/Hann；513 bin 对数谱 → DCT 倒谱" | 特征用的 513 bin 对数谱来自 **WORLD CheapTrick**，STFT 只用于第 7 步移植 | `scripts/stft_env_20261024.py` 的 `predict_logsp()` 调 `synth_eval.analyse()`（WORLD），模型就是在这种谱上训练的。用裸 STFT 幅度谱属于分布外输入，预测会崩 |
| 降调用 "127 抽头 Hamming-sinc 或 scripts 里同款 FIR" | 127 抽头，`fc=7.5 kHz` | scripts 里只有 `scipy.signal.resample_poly`（Kaiser 41 抽头），没有可直接照抄的 FIR；7.5 kHz 让 8–16 kHz 折返分量被压 ≥50 dB |
| SoundTouch 升调 | 已按要求用 SoundTouch | 因此**与电脑端 librosa 的 `pitch_shift`（相位声码器）不是同一算法**，两者不能做样本级 SNR 对比，见第 8.3 节 |

## 4. 板上噪声/电平相关的实测事实（影响判读）

- `x16`（32k→16k 之后）与原始 16 kHz 素材（同段语音）对齐 31 样本后 **SNR 46.8 dB**、幅度比 **0.9998**。
- SoundTouch 输出电平几乎不变（`xB rms / x rms = 0.997`）；librosa 的 `pitch_shift` 会**衰减 3.2 dB**（`0.694`）。所以"电脑端参考更安静"有一条与移植无关的原因。

## 5. 权重 blob 格式（`data/student_v5.blob`，小端）

```
char   magic[4]  "VCB1"
int32  version=1, in_dim=646, hidden=512, layers=4, out_dim=48,
       context=4, nceps_in=32, nceps_out=48, n_bins=513,
       fft_size=1024, frame_period_x10=100, sample_rate=16000
float  pitch_ratio
float  mu[in_dim], sd[in_dim]
float  dct_in[32][513], dct_out[48][513], synth[48][513]   # synth = pinv(dct_out).T
float  pitch_ratio(again)
per layer: float W[hidden][in_l], float b[hidden]
float  W_out[48][512], b_out[48]
```

`synth` 与 `dct_out` 只差 1.9e-9（DCT-II 行正交），仍然按 Python 的 `np.linalg.pinv` 原样导出，避免任何"用转置近似"的争议。

### 8.3 与电脑端参考链的端到端差异（可解释范围）

电脑端参考（`ref_pitch`：`ref_port.py --wav data/test_src_16k.wav --pitch 1.4`，librosa 相位声码器）与板端输出**不能做样本级 SNR**：两者音高算法不同（WSOLA vs 相位声码器），时间结构不同，实测最佳时延 +440 样本、SNR −9.3 dB、corr 0.21 —— 这个数字没有意义，只说明"相位不同"。

包络域（WORLD 分析两边输出，10 个频带，power dB）：

| bin 边界 | 0 | 4 | 8 | 16 | 32 | 64 | 128 | 192 | 256 | 384 |
|---|---|---|---|---|---|---|---|---|---|---|
| 板端 | −19.7 | −19.4 | −19.4 | −23.7 | −36.4 | −42.5 | −44.3 | −53.7 | −60.3 | −70.6 |
| 电脑端 | −25.8 | −25.6 | −25.6 | −29.5 | −41.3 | −46.1 | −50.0 | −57.9 | −60.0 | −76.9 |
| 差 | +6.1 | +6.2 | +6.2 | +5.8 | +4.9 | +3.6 | +5.7 | +4.2 | −0.3 | +6.3 |

- 中位 F0：板端 **188.7 Hz** / 电脑端 **188.4 Hz**（源 135.3 Hz，比值 1.395）→ **升调正确**
- 包络整体高 ~+6 dB（power），且形状基本平行 → 是"整体电平"差，不是音色差
- 成因（实测拆分）：
  1. librosa 的 `pitch_shift` **衰减 3.2 dB**（`xB/x = 0.694`），SoundTouch 几乎不衰减（0.997）→ 3.2 dB 与移植无关；
  2. 32k→16k 抗混叠把 7.5–8 kHz 压掉后，源信号的 `c0`（平均倒谱）偏移，模型把这点读成"该抬包络"：同一段语音 `median_gain_db` 从 **+0.182 dB**（真 16 kHz 输入）变成 **+3.305 dB**（32k 路径后的 16 kHz）→ 约 +3 dB 幅度；
  3. 其余是 `x16` 与素材本身的细微差异（46.8 dB 重采样残差）经模型放大。
- 结论：**+9.5 dB 的电平差可完全解释**，但意味着**这个模型对输入端 7.5 kHz 以上的谱形很敏感**，播放时必须给输出留余量。

## 10. RTF 与预算对比（关键结论）

### 10.1 实测分阶段耗时（4 s 音频，预算 4000 ms）

| 阶段 | ms | RTF | 说明 |
|---|---|---|---|
| DIO（两遍合计） | 208.3 | 0.052 | |
| StoneMask（两遍） | 283.7 | 0.071 | |
| CheapTrick（两遍） | 1234.4 | 0.309 | 每帧约 9 次 1024 点 FFT |
| D4C（仅第一遍） | 1470.2 | 0.368 | 只为 1 个特征维（`apmean`） |
| **MLP（401 帧）** | **3817.0** | **0.954** | 1.14 M 参数 × 401 帧 |
| SoundTouch | 193.0 | 0.048 | |
| STFT+ISTFT（401×2 次 FFT） | 521.5 | 0.130 | |
| 16k→32k + S24 打包 | 185.0 | 0.046 | |
| **合计** | **8268.9** | **2.067** | `analysis_rtf 1.613`，`render_rtf 0.177` |

### 10.2 与预算对比

**目标 ≤1.0，实测 2.067，差 2.07 倍（需再省 4.27 s）**。分阶段看：

- **MLP 单独就 0.954**，几乎吃掉全部预算；
- WORLD 两遍合计 3.34 s（0.84），其中 **D4C 1.47 s 只为一个 68 维特征里的 1 维**；
- 渲染侧（STFT 0.13 + 重采样 0.05 + SoundTouch 0.05）很轻，**瓶颈全在分析侧**。

已做过的优化及实测收益：

| 优化 | 前 | 后 | 说明 |
|---|---|---|---|
| MLP 逐帧 → 一次搬 16 帧权重 | 9683 ms（含 WORLD） | — | 内存受限，权重 4.6 MB 每帧全读一遍 |
| MLP 分块 GEMM（NB=8 帧 × JB=8 神经元） | 8700 ms | **3817 ms** | 激活块 16 KB 落在 L1，内层 64 MAC/16 次加载 |
| 整包 `-O3` | 539 ms(主机) | 553 ms | 无收益，不采用 |

（板上二进制在 MLP 优化后**总 RTF 3.26 → 2.07**；输出逐字节不变。）

### 10.3 阶段 2 提速路线（按实测收益排序）

| 方案 | 预计省 | 预计 RTF | 风险 |
|---|---|---|---|
| MLP 权重 int8（4× 少流量，int32 累加） | 2.5–2.8 s | 1.4 | 需要重新验证精度（目标波形 SNR>60 dB），偏离"与 Python fp32 完全对齐" |
| 双核：两遍 WORLD 并行 + MLP 按帧切两半 | 2.0–2.4 s | 1.1–1.2 | pthread 静态链接；核间内存带宽 |
| STFT/ISTFT 用 float32 FFT | 0.26 s | | 数值略变（仍 >100 dB） |
| D4C 隔帧算 + 插值（或换平坦度近似） | 0.7–1.4 s | 0.8–0.9 | **改变模型输入**，必须重新验证音质 |
| 以上 1+2+3 | ≈3.0 s | **≈0.95** | int8 需验收 |

只靠"双核 + float FFT"约 1.1–1.2；要真正进到 1.0 以内，**必须动 MLP 精度或 D4C**，这属于阶段 2 的算法决策，需要你确认是否可以接受（前者影响"与 Python 逐位对齐"的验收口径，后者影响音质）。

### 10.4 阶段 2（实时）还需要做的事

1. **流式切片**：WORLD 非因果，按 200 ms `prefill_ms` + 每次 160 样本 hop 的滑动窗口做，窗口之间重叠、包络只用窗口中心段；`prefill_ms`/`normal|fifo|fifo_io` 参数位已经在 CLI 里。
2. **逐帧预算**：16 ms/帧。当前单帧成本 ≈ 20.6 ms（8268.9/401），即使双核也要 ≈10 ms/帧，所以阶段 2 必须先把上面的提速做完。

## 11. 遇到的坑（全部已解决，按发现顺序）

1. **没有主机 C++ 编译器**：`g++/make/cmake/cl/msys2` 都不在 PATH。最后用 Vivado 自带的 MSYS2 GCC 6.2（`D:\Vivado\Vivado\2018.3\msys64\mingw64\bin\g++.exe`）做桌面侧构建，但必须把该目录**加进 PATH**，否则 `cc1plus.exe` 找不到 DLL，编译**静默返回 1**、无任何输出（白查半小时）。
2. **SoundTouch 头文件不全**：`include/` 只有公开头，`AAFilter.h`、`TDStretch.h` 等内部头在 `source/SoundTouch/`，要一起拷。
3. **SoundTouch 非 x86 缺符号**：`FIRFilter::newInstance()`/`TDStretch::newInstance()` 无条件调 `detectCPUextensions()`，x86 实现文件在 ARM 上编译成空 → 自己写 `src/st_cpu_stub.cpp`（注意是 **C++ 链接**，不能加 `extern "C"`）。
4. **Windows 文本模式 stdin 把 0x1A 当 EOF**：读 S24 原始流只读到 11414 B 就报 `short input`。桌面构建加 `_setmode(_fileno(stdin), _O_BINARY)`。
5. **模型 blob 悬垂指针**：`load_model()` 里 `std::vector<uint8_t> buf` 是局部变量，返回的 `Model` 只存指针 → 前几个阶段"看起来正常"，跑到 MLP 才 SIGSEGV（`gdb` 定位在 `float s = Bb[j]`）。改为全局 `g_blob` 持有。
6. **127 抽头抽取器的半样本时延**：`(127-1)/2=63` 个 32 kHz 样本 = 31.5 个 16 kHz 样本，非整数会毁掉对齐比较。取抽取起点 `off=1` 使群延迟变成整数 **31** 样本；插值方向保持 `off=0`（延迟 63 个 32 kHz 样本，本身就整数）。
7. **`dump_f32` 用 `sizeof(float)` 写 `double` 数组**：只写了一半字节，dump 全是 NaN（但 stdout 波形一直是对的，差点误判）。改成 double→float 重载。
8. **dump 目录 == 输入文件目录**：程序把自己的 stdin 文件覆盖了，下一次运行读到垃圾，出现"同一份代码两次结果不同"的假象。输入和 dump 分目录。
9. **S24_LE 是 4 字节不是 3 字节**：板上 `S24_LE` 是 32-bit 容器 + 24 位左对齐，第一版按 3 字节打包，长度对不上（1,024,000 vs 768,000）。
10. **测试输入的高频塌陷**：先用 `scipy.signal.resample_poly` 直接 16k→32k，它默认 41 抽头，4 kHz 以上就滚降，导致模型 `c0` 偏移、输出虚高 +10.8 dB。改成 127 抽头 `fc=7.8 kHz` 后降到 +3.3 dB（剩余差异见 8.3）。
11. **MLP 逐帧推理是内存瓶颈不是算力瓶颈**：4.6 MB 权重 / 帧，板上 24 ms/帧。只做"批处理"反而更慢（激活块 32 KB 反复冲刷 L1）；必须 **2 维分块**（8 帧 × 8 神经元）才降到 9.5 ms/帧。
12. **`-o3` 属性写法**：`__attribute__((optimize("O3")))` 只影响函数，`-ffast-math` 绝不能用（会动 WORLD 数值）。
13. **PowerShell 的坑**：原生命令 stderr 会被当异常（编译"失败"其实只是警告）；不支持 `<` 重定向（用 `cmd /c`）；`-replace` 的替换串里 `$'` 有特殊含义（改了正则被悄悄吞掉）；`$(...)` 在双引号里要先反引号转义再传给板端 shell。
14. **板上没 `ldd`**：ELF 架构只能主机侧用字节头 + SHA 校验（静态产物本来也不需要）。
15. **主机内存被其它任务占满**：并发在跑训练任务时 `torch`/OpenBLAS 报 `Memory allocation still failed`、`powershell 0x800705af`。用 `OMP_NUM_THREADS=1`/`OPENBLAS_NUM_THREADS=1` 压住，必要时重试。
16. **`download_board.ps1` 不建父目录**：`WriteAllBytes` 报错，需先 `mkdir`。
