# 分析端压榨：档位实测与验收表（阶段 2 补充 2）

- 日期：2026-10-25
- 目标：不改模型输入分布，把分析端再压 ~30%，让 300/500 ms 块的余量转正、underrun 归零
- 产物：`build/vc_stream_arm` @ `83257578…`（804,424 B），板上 `/tmp/vc/vc_live`
- 结论：**300 ms 块 + `--preset live` 做到了 0 欠载、延迟 585 ms（连跑 3 次全 0）**，但代价是 CheapTrick 隔帧带来的 identity −0.032 / CER +0.077（UTMOS 反而 +0.031）。**总压缩 13%，没到 30%**。

## 1. 验收表（想让你选的那张）

`4 s` = 板上批处理整段耗时；B=300/500 = 流式块长；延迟 = B + 该块处理耗时；欠载 = 12 s 音频里 aplay 的 underrun 次数。

| 档位（开关） | 4 s 耗时 | RTF | 波形相关 | identity | UTMOS | CER | B=300 proc / **延迟** / 欠载 | B=500 proc / **延迟** / 欠载 |
|---|---|---|---|---|---|---|---|---|
| **L0 默认**（fp32，不隔帧） | 3,887 ms | 0.972 | 1 | 0.6369 | 2.1040 | 0.0769 | 319 / 619 / **18** | 522 / 1,022 / **15** |
| L1 `--sm-stride 2` | 3,800 ms | 0.950 | ≈1 | 0.6343 | 2.1046 | 0.0769 | — | — |
| L2 `--sm-stride 2 --mlp-int8` | 3,726 ms | 0.931 | — | — | — | — | 288 / 588 / **2** | 483 / 983 / **1** |
| L3 `--ct-stride 2` | 3,540 ms | 0.885 | 0.9968 | 0.6028 | 2.1430 | 0.1538 | — | — |
| L4 `--ct-stride 2 --sm-stride 2` | 3,459 ms | 0.865 | 0.9968 | ≈0.605 | ≈2.14 | 0.1538 | 287 / 587 / **2** | 483 / 983 / **1** |
| **L5 `--preset live`**（ct2+sm2+int8） | **3,381 ms** | **0.845** | **0.9968** | **0.6047** | **2.1351** | **0.1538** | 285 / **585** / **0** ✓ | 480 / 980 / **1** |

（L5 的 B=300 连跑 3 次全部 0 欠载；L4 与 L2 在同条件下稳定 2 次欠载。）

**你的验收线**：
- 300 ms 块：欠载 0 ✓、延迟 ≤700 ms（585 ✓）→ **达标（仅 L5）**
- 500 ms 块：欠载 0 ✗（1 次）、延迟 ≤1100 ms（980 ✓）→ 延迟达标、欠载差 1 次
- CheapTrick 隔帧门槛「相关 ≥0.995 且 UTMOS 降 ≤0.03」→ **通过**（0.9968 / UTMOS 反而 +0.031）

## 2. 每一档做了什么、代价在哪

### 2.1 StoneMask 隔帧（L1）——几乎免费，建议无条件采纳

`--sm-stride 2`：StoneMask 是逐帧精修 f0，隔帧算 + 在 log-f0 上插值（浊/清边界不平滑，只在两侧都浊音时插值）。

- 省 **87 ms**（3,887 → 3,800）
- identity −0.0026、UTMOS +0.0006、CER 不变、波形相关 ≈1

**f0 平滑度确实高，你的判断对。**

### 2.2 CheapTrick 隔帧（L3）——省得多，但会动音色

`--ct-stride 2`：CheapTrick 的帧网格是入参，隔帧算后在**对数功率谱上做 Catmull-Rom 三次插值**（比线性略好：相关 0.9966 → 0.9968）。

- 省 **347 ms**（3,887 → 3,540），是这次唯一的"大件"
- 波形相关 0.9968 ✓、UTMOS **+0.031**（更好，因为包络更平滑、少了逐帧抖动）
- **但 identity 0.6369 → 0.6047（−0.032）、CER 0.0769 → 0.1538（翻倍）**

一次 4 s 单窗的 identity 测量噪声约 ±0.02，所以 −0.032 处在"可辨但不大"的区间；CER 翻倍是因为 4 s 只有约 13 个字，多错 1 个字就翻倍（绝对差 1 个字）。
在仓库自带门禁里它仍然全过：identity 0.6047 ≥ 0.45 ✓、cer_rel −0.0337 ≤ 0 ✓。

`--ct-stride 3` 不达标：波形相关 0.9932（<0.995），已否决。

### 2.3 fft_size 1024 → 512：**没有试，因为结构上不可行**

CheapTrick 的 bin 数由 fft_size 决定（`fft_size/2+1`）。512 点 → **257 bin**，而模型的第一层 DCT 是 **32×513**、包络是 513 bin。降到 512 等于换掉模型的输入维度，必须重训 DCT/模型——这正是"不改模型输入分布"禁止的事。要把 257 插值回 513 又会在 7.5 kHz 以上凭空造谱，属于改变分布。所以这一项**按约束跳过**，不是没时间做。

### 2.4 int8（L2/L5）——保留为开关，作用是让 300 ms 刚好翻过线

- 单独看：总时间 −2.4%（MLP 段 −11%），指标不降（UTMOS −0.008、身份 +0.003）。
- 它在这里的真正作用：把 B=300 的每块耗时从 287 压到 285，**刚好把 2 次欠载变成 0 次**。也就是说 L5 的"0 欠载"余量只有 15 ms（5%），**属于刀刃上**。

## 3. 结论与建议

1. **总压缩 13%（3,887 → 3,381 ms），没到 30%。** 剩下的大件是 MLP（L5 里仍有 1,674 ms，占 50%）和 WORLD 第一遍（701 ms）。MLP 已证明是**指令发射受限**（int8 减 4 倍流量只换来 11%），再往下必须重写 GEMM 微内核（4×4 分块 + 减少 vdup），估计能再挖 1.5–2 倍——那是几个小时的重活，不是今天的收尾。
2. **要"300 ms 块 0 欠载"→ 用 L5（`--preset live --stream 300`），延迟 585 ms**；但请接受 identity −0.03 / CER 多错 1 个字。已连跑 3 次验证 0 欠载。
3. **要保住 identity/CER → 用 L1 或 L2（只隔 StoneMask），块长 500 ms**：延迟 983 ms、12 s 内 1 次欠载。这符合你说的"当前算法链只能 500 ms 块 + N 次欠载"，N=1。
4. **500 ms 块做不到 0 欠载**：proc 480 vs 500，余量 20 ms（4%），任何调度抖动都会掉一次。这条我明确说清楚：**500 ms 块 = 1 次欠载/12 s，且与 start-delay 无关（已试 2 s/3 s/4 s 都一样）**。
5. 20 ms hold-back 在 B ≥ 200 ms 时都是块长 ≤10%，够用；若跑 B=100 ms 建议 `--fade-ms 10`。

**默认配置没动**（`ct_stride=1, sm_stride=1, fp32`，RTF 0.970，削波 0）——隔帧与 int8 都走开关，`--preset live` / `--preset safe` / `--preset off` 三档，演示时不会抄错参数。
