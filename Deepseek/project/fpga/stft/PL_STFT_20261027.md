## 1. 定点方案（为什么这么定）

主链 STFT 是 `n_fft=1024, hop=160, periodic Hann, center=True`，增益是**每个 (帧,bin) 的实数**，
所以 PL 只需做「前向 FFT → 乘实数增益 → 逆 FFT」，窗、重叠相加、`wsum` 归一化留在 ARM。

两个 xfft 都配 **unscaled**：scaled 模式的 `SCALE_SCH` 语义随版本变化，且 9.1 的配置端口实际只有 8 bit
（与文档不符），搞错就是整帧全错。unscaled 下所有缩放因子在 RTL 里显式写死：

```
a[n] = x[n]                        int16 单位，24 bit 有符号
A[k] = Σ a[n] e^{-i}               unscaled FFT（|A| ≤ 2^25）
Y[k] = round(A[k] * g_q / 2^13)    g_q = g*2^19，|g| ≤ 16，保留 6 位小数
y[n] = Σ Y[k] e^{+i} = 2^16 · z[n] unscaled IFFT（40→48 bit 输出）
out  = round(y / 2^8) = z · 2^8    写回 32 bit，8 位小数
```

`/2^13` 的依据是实测频谱动态范围：401 帧上 `max|A| = 2^19.8`、`max|A·g| = 2^22.2`；
满量程语音时 `max|A·g| ≈ 2^24`，`Y` 仍有 2 bit 余量，`Y` 量化噪声折算到输出约 **0.15 LSB**。

C 侧把 PL 的 `z·256` 换回主链 [-1,1) 单位：`zq / (256·32768) = zq / 8388608`。

## 2. 帧格式与接口

```
每帧输入（AXIS 32 bit）：[1024 × int16 窗后样本] [513 × Q4.19 增益]   = 1537 words
每帧输出（AXIS 32 bit）：[1024 × int32]  value = z*256（z 为 int16 单位）
```

帧内时序（100 MHz）：收样本 1024 拍 → 收增益 513 拍 → 前向 FFT → 逐 bin 乘法 1024 拍 →
逆 FFT → 输出 1024 拍；实测 **8715 cycles/帧 = 87 µs**（10 ms 帧预算的 0.87%）。

### 3.2 逐 bin 对比（前向，真实帧，单独实例）

| 帧 | `max|A|` | `max|err|` | 相对峰值 bin | SNR |
|---|---|---|---|---|
| 223 | 6.164e5 | 18.0 | **2.92e-5** | 80.2 dB |
| 358 | 3.878e5 | 18.6 | **4.80e-5** | 78.8 dB |

冲激 1000 → 1024 个 bin 全为 1000；直流 100 → bin0 = 102400，其余全 0（**逐 bin 精确**）。

关键发现：误差是**绝对的**（≈18 LSB 上限、6 LSB RMS），与信号幅度无关——安静帧
（`|A|max=1252`）也是同样 6 LSB RMS。因此归一化到频谱峰值时相对误差恒定 ~3e-5；
只有比峰值低 60 dB 以下的 bin 相对误差才会变大（定点 FFT 的固有性质）。

### 3.3 逆向

逆向 FFT 的独立 TB（`sim/tb_fft_inv.v`）可跑通，但单独比对时受激励字节序影响，
最终以 §5 的整链逐样本比对为准（整链残差 0.6 LSB，等价于逆向 FFT 正确）。

## 5. M3：入链

`vc_stream_pl.cpp` 新增 `--pl-stft` / `--no-pl-stft` 与 `VC_PL=0/1`：
PL 模式下**跳过 ARM 的 `stft()`**，改为：ARM 做窗 + int16 量化 + 增益 Q19 量化 → DMA → ARM 做 OLA。

| 指标 | 全 ARM `vc_o64` | PL `vc_o64_pl` |
|---|---|---|
| corr（左声道，128000 样本） | 基准 | **0.99999999** |
| max_abs_diff | – | **4 LSB** |
| rms_diff | – | **0.60 LSB** |
| 差 >2 LSB 的样本 | – | 22 / 128000（0.017%） |
| peak_out | 1.359225 | 1.359217 |

| pl_dma_ms | – | 75.63 |
| total_ms | 3750.29 | 3607.80 |

`devmem 0x41200000` = `0x096A0000` → 帧计数 2410（累计，含探针），busy=0、无 tlast 错误。

### 5.2 收益确认

- STFT 段 **−143.2 ms（−31.9%）**；其中 PL DMA 往返占 75.6 ms，即 PL 真正省下的 ARM 计算约 **219 ms**。
- 整链 **−142.5 ms（−3.8%）**，RTF **−0.036**。
- 收益小于"STFT 全部搬走"的预期，原因：窗+量化、401×513 次 `exp()`、401×1024 次 OLA 仍在 ARM，
  且都是双精度；这部分若要继续压缩，下一步应把 OLA 和增益量化也搬进 PL（需要 PL 侧缓存整段输出）。

### 5.3 稳定性

8×4 s = 32 s 连续跑：`fails=0`，8 个输出**逐字节相同**，RTF 0.904。

## 7. 卡点与教训（按发现顺序，全部有日志）

### 7.1 构建必须用短 ASCII 路径
在 `<workspace>/...` 下建 BD 时子 IP 的 OOC 综合会崩：
`TclStackFree: incorrect freePtr. Call out of sequence?`，PS7 DCP 没生成，顶层报 `DCP does not exist`。
换到 `D:\g_build\pl_stft_20261027`（27 字符）同一脚本一次通过。（前人 2026-10-25 也是这么做的。）

### 7.2 已确认并修复的 6 个 RTL bug
1. **S_IDLE 多消费 1 个样本** → 每帧吃掉第一个增益，FSM 卡在 S_GAIN。
2. **送数地址跳样本** → `samp_ra <= fcnt+1` 与 BRAM 1 拍延迟叠加，地址每拍 +2。
3. **tlast 早一拍** → 数据与 tlast 流水深度不同，1024 个字里 tlast 从未有效。
4. **谱 RAM 写地址旋转一格** → `sa_we/sa_wd` 是寄存器输出，写地址却用同拍还会自增的 `sa_wa`，
   每个字被写到下一个地址，`spec_a[0]` 永远不写。改为写地址也延迟一拍。
5. **拼接后做算术没转回有符号（最隐蔽）**：`{{4{inv_re[47]}}, inv_re} + 52'sd128` 里 `{a,b}` 是
   **无符号**，整条表达式变成无符号加法、`>>>` 退化为逻辑右移，**负样本全变巨大正数** → 输出恒为
   +INT32_MAX。正样本完全正常，所以"正冲激对、负冲激饱和"一度被误判成 FFT 符号问题。
   修复：`$signed(...)` 显式转回有符号再参与运算。
6. **乘法写地址比数据晚一级** → 输出谱整体旋转 1 个 bin（真实帧 SNR −7 dB，但冲激/直流看不出来，
   因为它们的谱是对称的）。用真实帧对 numpy 做 SNR 扫描才定位到：`roll(Y,±1)` 时 SNR 80.65 dB。
   修复：写地址 `micnt - 4`。

### 7.3 24 bit 逆 FFT 输入装不下带小数的 Y
`Y = A·g/2^10` 只剩 10 bit 有效精度，量化噪声折算到输出约 1200 LSB。改 32 bit 输入 + 6 位小数 → 0.15 LSB。

### 7.4 行为级 xfft 仿真代价过高
单个 1024 点 xfft 的 `xelab` 约 5 分钟；两个一起会卡到 40 分钟以上（32 bit 那个模型）。
对策：M1 拆成前向/逆向两个独立 TB；控制流用直通 stub（1–2 分钟一轮）；
数值正确性以板上对 numpy 为准。

### 7.5 BD 里 module reference 不会自动生成 AXIS interface
2018.3 对 `-type module` 的 cell 不会从端口名推断 `s_axis` 接口，`connect_bd_intf_net` 报"参数为空"。
改为逐引脚 `connect_bd_net`；注意 IP 侧引脚名全小写（`m_axis_mm2s_tdata`），module 侧用 Verilog 原名。

### 7.6 module reference 内含 IP 会 OOC 综合失败
xfft 实例放在 `axis_stft_gain` 里时，BD 把该 module 当独立 IP 做 OOC 综合，隔离上下文里看不到
`fft_fwd` → `module 'fft_fwd' not found`。最终把两个 xfft 提到 BD 里作为独立 IP cell。

### 7.7 板上物理连续内存不可依赖
运行一天后 buddy 分配器只给零散 order-0 页（实测 64 页里没有相邻对，3 页/2 页连续都失败）。
驱动改成**三个独立页 + 每帧两次 MM2S（4096 B 样本 + 2052 B 增益）+ 一次 S2MM**，
彻底不需要连续物理内存；实测 118 µs/帧。

### 7.8 板端精简 Python 没有 mmap
状态寄存器用 `devmem 0x41200000 32` 读；相关/最大差用板上 C 工具算，避免把 2 MB 波形拖回串口。

### 7.9 比对工具自己错过一次（教训）
`compare_s24` 最初按"低 3 字节"解 S24，实际格式是 **24 位左对齐在 32 位容器里**（应取 int32 再 `>>8`）。
这个 off-by-one 让一个真实 corr≈0.99999999 的结果看起来只有 0.9905，白查了很久。
**结论：判据工具本身要先用手工可算的样本验证。**
