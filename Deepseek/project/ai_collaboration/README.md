# AI 协作记录（官方硬要求）

> 本目录按赛事要求提交：**提示词要点、模型给出的关键决策、被证伪的假设与纠正过程、最终沉淀的方法论**。
> 它不是"我们用了 AI"的声明，而是一份**可核对的工作日志**：每一个结论都指向仓库里的文件、
> 数字或原始日志。

## 1. 记录规则（先定规则，再记录）

1. **只记录改变了下一步动作的交互**。闲聊、"帮我写个函数"这种不进来。
2. **每个条目必须有可核对的落点**：一个文件、一段日志、一个数字。没有落点的记为"未验证"。
3. **被证伪的假设单独成段**，写清：当时的判断 → 什么实验推翻了它 → 现在的判断。
   这一栏是本目录最有价值的部分，因为它是**别人不必重复踩坑**的部分。
4. **不美化**：模型（包括本记录的作者）猜错的地方照写，包括"猜错两次"。
5. **区分"模型说的"和"实测的"**：表格里的 `[实测]` / `[推断]` / `[未验证]` 标记不能省。

## 4. 模型在本次协作里实际承担的角色

| 角色 | 具体做什么 | 例子 |
|---|---|---|
| 代码生成 | 把算法从 Python 逐项翻译成 C/RTL/Tcl，并保证数值语义一致 | `vc_stream.cpp` 的 646 维特征、`axis_pitch_shift.v` 的定点变调 |
| **假设提出者** | 提出"瓶颈在哪""为什么不对"的候选解释 | "MLP 是内存带宽受限"（后被推翻） |
| **假设的证伪者** | 设计能推翻自己的实验，并读结果 | 4 帧/8 帧/int8 三组流量对照实验 |
| 记录者 | 把每轮结论写成带数字的报告 | `board_c_20261025*.md`、`pl_build_20261025.md` |
| 交付整理 | 目录、命名、SHA、复现步骤 | 本参赛包 |

> 一句话总结这次协作的有效模式：**让模型同时提出假设和证伪实验，并且要求它把"实验没通过"
> 也写进报告**。凡是只让它"给结论"的地方，几乎都返工了；凡是让它"给判据 + 跑给看"的地方，
> 一次就过。

## 5. 如何检验这份记录不是事后编的

1. 每个条目里的数字都能在对应文件里 grep 到（例如 `74.86`、`0.9793`、`49248`、`8378`）。
2. 报告里保留了**失败版本的产物**：`fpga/report/m3_compare_output.txt`（FAIL，16 样本）、
   `board_c_20261025_int8_latency.md` 第 0 节的自我更正、`docs/` 里对 2018.3 的说明。
3. `prompt_log.csv` 的 `outcome` 列里 `refuted` 的比例（12/28）本身就不像"事后美化"的记录。
4. 原始对话导出（聊天记录）由团队按赛事要求另行保存；本目录是可读摘要 + 可核对落点。
