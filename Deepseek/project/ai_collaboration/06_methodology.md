# 06 方法论：把"猜测"变成"判据"

日期：2026-10-26
本文件是本轮协作的**最终沉淀**，也是这个参赛包所有文档的共同写作规范。

---

## 1. 六条做法（每一条都由前面的失败换来）

### 1.1 先定门限，再动手

**反例**：`--ct-stride 2` 的相关是 0.9968，`--ct-stride 3` 是 0.9932。
如果门限最后才定，0.9932 完全可能被"看起来差不多"放过。
**做法**：优化方案开工前，把"相关 ≥0.995、UTMOS 降 ≤0.05、identity 降 ≤0.01"写进任务书，
做完只做"过/不过"的判断，不做"要不要勉强接受"的讨论。

### 1.2 每个结论必须能指向一个文件

**反例**：口述的"音高 +12 半音"（实际 +6.2，见 01 §4.3）。
**做法**：报告里每个数字后面跟 source；本包的 `metrics/metrics.csv` 每行都有 `source` 列。
没有落点的结论，标注 `[未验证]` 或直接不写。

### 1.3 比对前先保证"输入同一份"

**反例**：74.86 dB 被当成实现 bug（实际是 1 ulp 输入差被网络放大 10³ 倍，见 04 §4.1）。
**做法**：跨实现比对必须提供"喂同一份输入"的钩子（`--in-f32-16k`、`--xB-f32`）。
没有这个钩子，任何 SNR 都不能用来判断代码。

### 1.4 先看"错的形状"，再看代码

**反例**：16 个样本为 0 被猜成"RTL 复位没清"。
**做法**：形状特征化 —— 长度、对齐、是否全 0、是否只在首轮、误差是否同号、是否落在块边界。
四条形状规则已经固化进 `skill/golden_reference_compare` 的 `verdict_text()` 和
`skill/dma_cache_coherency/diag_checklist.md`。

### 1.5 单变量、强对比的实验优先

**反例**："int8 是带宽问题"（见 03 §3.1）。
**做法**：设计那种"如果假设成立，结果应该差 4 倍；如果不成 test，最多差 10%"的实验。
流量 ÷4 只快 11%，一句话就否掉了带宽假设。**这种实验比 profiler 便宜得多。**

### 1.6 公开更正，而不是悄悄改

**反例**：stage-2 报告曾把 underrun 归因于"内存带宽与 DMA 争用"。
**做法**：在下一份报告的第 0 节写"先更正一条我上轮的错误结论"，附三组对照数据。
**理由**：评委会看的是"你能不能发现自己错"，不是"你有没有错过"。

## 2. 因为 AI 建议而**新增**的验证（9 项）

| # | 验证 | 为什么加 | 结果 |
|---|---|---|---|
| 1 | 逐阶段 dump 比对（12 级中间量） | 只看最终波形无法定位 | 121.71 dB，各阶段 max\|Δ\| 已知 |
| 2 | "喂同一份 float32 输入"的钩子 | 排除 1 ulp 放大 | 74.86 → 126.16 dB |
| 3 | 权重流量三组对照（4/8 帧、int8） | 检验带宽假设 | 流量 ÷4 仅快 11% |
| 4 | 输出逐字节可复现（3 次运行 + 3 个构建） | 排除随机性 | ±0.1%，逐字节相同 |
| 5 | 恒等比例（ratio=65536）SHA 对照 | 证明"比例真的生效" | 输出 SHA == 输入 SHA |
| 6 | DMA 首轮 vs 复用缓冲对照 | 抓缓存回写 | 16 样本 → 0 |
| 7 | 隔帧/单遍/频轴映射的相关门限 | 防止"差不多" | 三项被否决 |
| 8 | 跨架构（ARM vs x86）同输入比对 | 排除编译器/glibc 差异 | 139.38 dB，max\|Δ\| 2.4e-7 |
| 9 | 重编译产物 SHA 对照 | 证明"源码→二进制"可复现 | `pitch_dma_mem` 逐字节相同 |

## 3. AI 适合做 / 不适合做的事（本轮经验）

| 适合 | 不适合 |
|---|---|
| 把算法逐项翻译成 C/RTL，并保持数值语义 | 判断"听众觉得好不好听" |
| 设计能证伪自己的实验 | 决定"要不要为了进度牺牲质量" |
| 读完几百行日志找出异常行 | 替代实测（它说的"应该"经常错） |
| 把结论写成带数字的报告、整理交付结构 | 现场接线/听音/确认硬件状态 |
| 记住"上次为什么否决了方案 B" | 判断赛事规则的解释权（必须人来核对原文） |

**一句话**：让模型当"提出假设 + 设计证伪实验 + 记录结果"的角色，
不要让它当"给最终结论"的角色。前者一次就过，后者几乎都要返工。

## 4. 这套方法论在别的题目上怎么用

1. **换题目**：门限先行、单变量强对比、形状分类这三条与领域无关。
2. **换板卡**：把"平台级事实"（HP 口非一致、cacheflush 只清 L1、镜像要 4 字节反转）
   做成 checklist，换板时只改常数。
3. **换团队**：`prompt_log.csv` 的 `outcome=refuted` 列就是"不要重复的路线"清单。
4. **写报告**：`skill/golden_reference_compare/report_template.md` 的表格格式
   可以直接套到任何"实现 vs 参考"的题目上。
