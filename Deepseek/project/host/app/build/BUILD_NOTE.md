# build — 关于这个目录里的产物

## 1. 里面是什么

| 文件 | 大小 | SHA-256（前 16） | 说明 |
|---|---|---|---|
| `vc_stream_arm` | 804,424 B | `557cc08a67fadc6e` | 静态 ARM ELF（`-O2 -static -s`），**2026-10-26 在参赛包目录内重编译** |
| `vc_stream_arm.json` | — | — | 构建元数据（路径/字节数/SHA/编译选项） |

## 2. 与"板上实际跑过的那个二进制"的关系（必须读）

| 项 | 值 |
|---|---|
| 板上跑出全部结果的 `vc_stream` | 804,424 B，SHA `83257578…`（见 `metrics/logs/board_c/board_final_telemetry.json` 对应的构建记录） |
| 本目录重编译的产物 | 804,424 B，SHA `557cc08a…` |
| 结论 | **大小完全相同、SHA 不同**；本目录这一份**没有在板上验证过** |

差异原因（已确认不是代码差异）：

- 编译选项、编译器、第三方源码、`vc_stream.cpp` 全部逐字节一致；
- C++ 的**局部静态符号名**参与布局，而 GCC 的随机种子默认由**输入文件路径**派生；
  换目录重编译 → 符号/布局微变 → 字节不同、大小相同。
- 反证：同一工具链重编译**单文件 C** 工具 `pitch_dma_mem.c`，产物 SHA 与板上运行的
  二进制**逐字节相同**（`fe312bb1…`），说明工具链本身没有漂移。

## 3. 怎么用

- **只想上板跑**：直接用它（功能等同，但属于"未在板验证"的产物；
  若要严格复现报告里的数字，请以板上已验证的那份为准）。
- **想严格复现**：在自己机器上 `..\build_arm.ps1` 重编译，并接受 SHA 会因路径不同而不同；
  数字复现的判据是**遥测里的耗时/指标量级**，不是二进制 SHA。
- **想核对功能**：编译后先在主机侧跑 `build_host.ps1` 的产物做数值自检（见 `..\README.md` §3）。

## 4. 不要做的事

- 不要用 `-O3` 或 `-ffast-math` 替换 `-O2`：实测无收益（-O3 更慢），`-ffast-math` 会改变
  WORLD 的数值结果，破坏与 Python 参考的对齐。
- 不要去掉 `-Wl,--whole-archive -lpthread -Wl,--no-whole-archive`：静态 glibc 下
  `pthread_create` 会失效（详见 `report/failure_analysis.md`）。
