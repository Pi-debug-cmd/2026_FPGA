## 2. 逐条分析

### F1｜RTF 2.067 → 0.967：一开始把"算力"当成了瓶颈

- **现象**：4 s 音频 8269 ms，其中 MLP 3817 ms（0.95）、D4C 1470 ms、CheapTrick 1234 ms。
- **最初的判断**：MLP 参数多（1.14 M），算力不够 → 先做 int8、再做双核。
- **定位过程**：
  1. 逐帧推理 24 ms/帧 → 改成批处理 → **更慢**（激活块冲刷 L1）；
  2. 2 维分块（8 帧 × 8 神经元）→ 9.5 ms/帧（6.7×）；
  3. 再问"是不是带宽"→ 4 帧/8 帧/int8 三组流量对照 → **流量 ÷4 只快 11%**；
  4. 结论：**指令发射受限**，真正的解是"寄存器分块 + 显式 NEON + 双核"。
- **同类错误**：D4C 原来每帧算，其实它只贡献 68 维里的 1 维（`apmean`）；
  改成每 10 帧 + 插值，**直接跳过真实计算**，省 1315 ms。这一项比任何微优化都值钱。
- **留下的设计变更**：
  - `--ap-stride` 默认 10（1 = 精确参考）；
  - MLP 内核固定为 2 维分块 + NEON；
  - `--threads 2` 默认，失败回退串行。

### F2｜underrun：计算已经实时，整链仍然掉帧

- **现象**：工具本身 RTF 0.982（12 s 音频 11785 ms），但 `cat → vc_stream → aplay` 整链
  14758 ms、11 次 underrun。
- **第一次归因（错）**：内存带宽与 DMA 争用 → 上 int8 → **underrun 依旧**（11–39 次）。
- **正确归因**：整链 RTF 0.96–0.98 **几乎没有吞吐余量**，aplay 一争 CPU 就顶不住；
  与"少算 290 ms"关系不大（快速档省了计算，整链时间几乎不变）。
- **部分修复**：`--preset live`（ct2+sm2+int8）把 300 ms 块压到 285 ms，
  3 次连跑 0 欠载；但 500 ms 块仍差 1 次（480 vs 500，余量 4%）。
- **没修的**：500 ms 块。**明确结论**：在双核 A9 上，500 ms 块做不到 0 欠载，
  且与 start-delay（试过 2/3/4 s）无关。

### F3｜`p95 ≤ 100 ms` 不可达：这是算法选型问题，不是常数优化

- **推算**：延迟 = B + proc(B)。实测边际 RTF 0.95–0.97 + 每块 30–60 ms 固定开销。
  要做到 100 ms，需要 B ≈ 60–80 ms 且 proc ≤ 20–40 ms，即整链再快 2–3 倍。
- **同时** WORLD 分析本身需要 50–100 ms 的窗才能稳住 f0/包络。
- **结论**：在这条算法链上不可能。要达标必须换前端（去掉 WORLD，
  改 5–10 ms hop 的轻量 STFT 包络 + 更小模型）——那是另一个算法选型。
- **为什么写进报告**：因为"我们没试"和"结构上不行"是两件事，必须说清。

### F4/F5｜UTMOS 门禁仍未过，泄漏已由 O64 解决

- **数据（O64 定版，23.72 s）**：identity 0.7293（过）、UTMOS 2.2659（**不过** 2.30，差 0.034）、
  leakage_rel −0.0223（**过**，F5 已解决）；4 s 同片段 CER 0.1538（2/13 字，不过 0.15）。
  T4/48 阶旧版为 0.6373 / 2.1045 / +0.0157 / 0.0769，留作对照。
- **定位**：
  - 与电脑端 O64 参考 2.2681 只差 0.0022 → 不是"上板掉音质"；
  - 倒谱阶数 48→64 把 UTMOS 从 2.10 提到 2.23（4 s 同片段）/2.27（整段），仍未跨 2.30
    → **模型/算法上限**，不是实现问题；
  - 目标女性文件本身的 UTMOS 也在这个量级，说明这条链的 64 阶倒谱 + MLP 残差
    无法重建足够自然的细节。
- **可能的改进方向（未做）**：非周期成分建模、或用神经声码器替换 ISTFT。
  神经声码器这一条已在**另一条独立支线**上试过（F13，GAN 版，未入包），
  结论是"音色/内容/基频都对、只差声门相位谱"，见 F13。
  提高倒谱阶数已经做过（O64），不再列。每一条都要重训 + 重测四指标，超出本轮时间窗。
- 另：时间对比度后滤波的对照实验只 +0.067，未采用（`design_report.md` §6.5）。
- **诚实结论**：**这是本作品最大的短板，且不是靠调参能修的。**

### F6｜16 个样本被清零：最像"玄学"的一次失败

- **现象**：128000 样本中 16 个错，两段各 8 个、值全 0、32 B 对齐、只在首轮出现。
- **最初的判断**：RTL 复位没清干净（因为值恰好是 0）。
- **定位过程**：
  1. 第二次运行不复现 → 排除确定性逻辑错误；
  2. 错的长度恰好 32 B（A9 cache line）→ 高度怀疑缓存；
  3. 只加 `cacheflush()` → **仍然错**；
  4. 加 2 MiB（4×L2）冲刷 + `usleep(20 ms)` → **max_abs_diff = 0**。
- **根因**：`mmap`+`memset` 产生的脏零行留在 PL310 L2；DMA 写完之后 L2 把这些脏行回写，
  覆盖了 DMA 输出。ARM 的 `cacheflush` 只清 L1，不碰 L2。
- **留下的设计变更**：
  - 缓冲区改为"CPU 只用非缓存别名"；
  - 分配时强制 `cacheflush` + L2 冲刷；
  - 这条判读法固化成 `skill/dma_cache_coherency/diag_checklist.md` §1。

### F7｜74.86 dB：一次"差点写错结论"的比对

- **现象**：板端输出 vs Python oracle 只有 74.86 dB，而其它级是 121–139 dB。
- **第一反应**：C 实现有 bug。
- **纠正过程**：给 C 加 `--in-f32-16k` / `--xB-f32`，让它吃 oracle 用的**同一份 float32**，
  同一条对比升到 **126.16 dB**。
- **根因**：板上 C 内部用 double 的中间量，oracle 只能拿到 dump 的 float32（差 1 ulp）；
  4 层 512 的 GELU 网络对这个扰动放大约 10³ 倍。
- **留下的设计变更**：所有跨实现比对必须先做"输入同一份"的钩子；
  这一条写进了 `ai_collaboration/06_methodology.md` §1.3。

### F8｜"CheapTrick 只跑一遍"的三个方案全被否决

| 方案 | 相关 | 门限 | 结论 |
|---|---|---|---|
| 纯频轴映射 `logsp_b[b]=logsp_src[b/1.4]` | 0.9793 | 0.99 | 否决 |

### F10｜前人 RTL 的 49248 bin 全失配（复核别人的失败）

- **现象**：复数 exp 单元的 96 次调用 × 513 bin **全部失配**。
- **根因**：cos/sin 查表漏了 `frac` 线性插值。最小复现：
  `143940 × (−6439)/131072 = −7071`，而实际输出正是 −7071（= 只用 `LUT[j]`）。
- **状态**：补丁**已写在磁盘上的 RTL 里**（双地址 ROM + 两拍插值），
  但 `expunit_status.json` 的 `not_done` 明确写着"RTL 0 LSB 未达成 / 后综合 funcsim 未做"。
  **所以真实状态是"停在一个已知根因的补丁上，没人复跑"，不是"这条路走不通"。**
- **教训**：`not_done` 字段比 `status` 字段更值得读。

### F13｜神经声码器（GAN 版）：相位学不会，身份已追平

- **做了什么**：把 ISTFT 换成 77 万参数 HiFi-GAN 类生成器（判别器 240 万），输入仍是链上已有的
  56 维（32 阶倒谱 + logF0 + AP），训到 **371,700/400,000 步、12.93 h** 后于 13:38 主动停止。
- **结果（371k）**：UTMOS **1.368**（验证集 1.4032；T4 2.234、教师 3.594），但 **identity 0.726 已追平 T4 的 0.734**（200k→371k 停在 0.726–0.731，已饱和）、周期度 **0.856**（T4 0.884）、字错 **0.263**（T4 0.238）。
- **决定性诊断**：同一响度/时长下交换 STFT 两半再评分——换 T4 相位 UTMOS **+0.50～+0.52**，只换 T4 幅度 **+0.04**（≈+0.05）；118k 与 244k 两次测量完全一致，说明后 15 万步没再学到任何相位。
- **结论**：唯一短板是**声门脉冲相位谱**，不是音色、内容或基频——幅度谱已基本等于 T4。
- **为什么 40 min 数据不够**：G 只有 0.77 M 参数、约 40 min 音频（56 min 加权视图），而 HiFi-GAN 原版是 14 M G + 24 h 数据 + 约 250 万步；**数据少 100 倍、模型小 18 倍**，学得到谐波与包络，学不到相位。
- **相对上次纯回归版（相位平均、UTMOS 1.240）是质变**：输出从"与随机相位对照 1.2517 不可分的噪声"（周期度 0.50–0.58）变成"音色/内容/基频都对、只有相位不对的谐波语音"。
- **相对 T4 的音色差已不可闻**：identity 只差 0.008（单窗噪声约 ±0.02），听感差距全部来自相位粗糙度，不来自音色。
- **处置**：**未入包、未上板**；定版仍是 O64 + live，这条支线的价值是给"下一步该攻相位"提供了判据而不是一个可交付模型。

## 5. F12｜PL 与主链的集成（2026-10-27 已解决）

- **最终走的路**：不是把变调核接进主链，而是把 **STFT/IFFT + 逐 bin 频域乘法**搬进 PL
  （`fpga/stft/`）。原因：FFT 与 ARM 参考链**数学等价**，可逐样本比对；变调会改变相位、伤音质
  （详见 `PL_STFT_20261027.md` §1 与设计报告 §6.8）。
- **结果**：端到端 corr **0.99999999 / max 4 LSB**；STFT 段 **449.04 → 305.82 ms**；
  整链 **RTF 0.9376 → 0.9019**；资源 16,723 LUT / 22 BRAM / 76 DSP、WNS **+0.347 ns**；
  8×4 s 稳定（0 失败、8/8 逐字节相同）。
- **变调核的处置**：保留为**已验证的备用设计**（bit-exact、RTF 0.0078），
  与 STFT 版**互斥**——同一 PL 只能加载一个位流，切换需重载并重启音频消费者。
- **联测已补（2026-10-27）**：PL STFT + O64 + `--preset live` 同口径——4 s RTF **0.8237**、
  STFT 段 **451.3→309.5 ms（−142 ms）**、60 s/200 块处理 p99 **274.8 ms**、**0 欠载**；
  四项 identity 0.7324 / P10 0.6903 / 泄漏 −0.0343 / UTMOS 2.1532（仍差 2.30 门禁）。
- **仍未做**：OLA 与增益量化搬进 PL（下一步的收益点）。
  ⚠ 旧 `vc_o64_pl`（04-02 04:25）与 v5 位流**不兼容**（输出 ×32768、123991/128000 削顶），取数只用 `vc_pl_dbg3`。

## 6. 如果重来一次，排序会怎么变

1. **先做"结构上能跳过"的优化**（D4C 隔帧、第二遍 WORLD 并行），再谈近似 —— 能省掉 F1 的一半弯路。
2. **先建立"比对纪律"**（输入同一份、形状分类），再开始调数值 —— 能省掉 F6/F7 的反复。
3. **先把 PL 通路打通并接入主链**，再做算法压缩 —— 因为 PL 的收益（0.05 → 0.0078）
   比在 A9 上抠 10% 大得多。
4. **先测长稳与延迟分布**，再宣布"实时" —— 短时连跑不足以支撑"实时"这个词。
